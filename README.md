# Электронная библиотека — Клиент-серверное приложение

## Описание проекта

**Название разработки:** Клиент-серверное приложение «Электронная библиотека»  
**Назначение системы:** Предоставление пользователям доступа к электронным книгам и другим цифровым ресурсам.  
**Область применения:** Интернет-сервис для чтения и покупки электронных книг.  
**Масштаб развертывания:** Публичный онлайн-сервис.

Приложение позволяет пользователям просматривать, добавлять, удалять и читать книги в формате `.epub`. Система поддерживает управление авторами, жанрами, модерацией контента и персональными книжными полками.

---

## Архитектура приложения

Проект построен по принципу **Model-View-Controller (MVC)** и разделён на две основные подсистемы:

- **Хранилище данных** — реляционная база данных MySQL.
- **Подсистема обработки данных** — серверная логика на Node.js с использованием Express.

### Технологический стек

| Слой | Технологии |
|------|-----------|
| **Клиентская часть** | HTML, CSS, JavaScript, jQuery, EJS, AJAX |
| **Серверная часть** | Node.js, Express, NPM |
| **База данных** | MySQL, Sequelize (ORM) |
| **Инструменты** | Git, GitHub, Visual Studio Code, Docker |
| **Формат файлов** | `.epub` |

## Функциональные возможности

### Основные функции:
- Просмотр списка книг (главная страница, поиск, фильтрация).
- Управление персональной книжной полкой (добавление, удаление, отметка о чтении).
- Чтение книг в браузере.
- Загрузка и модерация книг (для модераторов).
- Управление авторами и жанрами.
- Регистрация и авторизация пользователей.
- Назначение ролей (суперадмин, модератор, пользователь).

### Роли пользователей:
| Роль | Права |
|------|------|
| **super_admin** | Полный доступ, создание и удаление ролей, назначение администраторов, просмотр аналитики |
| **admin** | Назначение модераторов, просмотр аналитики |
| **moderator** | Модерация контента: добавление/удаление книг, авторов, жанров |
| **user** | Чтение, добавление книг в свою библиотеку |

## База данных

Система использует **MySQL** в качестве СУБД. Все таблицы связаны внешними ключами через ORM **Sequelize**.

### Основные таблицы:
- `users` — данные пользователей
- `roles` — роли пользователей
- `user_roles` — связь пользователей и ролей
- `authors` — информация об авторах
- `books` — данные о книгах (название, описание, путь к файлу, цена, дата публикации и т.д.)
- `genres` — жанры
- `book_genres` — связь книг и жанров (многие ко многим)
- `user_books` — книги на полке пользователя
- `transactions` — история транзакций
- `action_history` — журнал действий (логирование операций)

## API и маршруты (основные)

### Книги
- `GET /books/featured` — получение рекомендуемых книг
- `POST /books` — добавление новой книги (только для модераторов)
- `POST /books/getAll` — получение всех книг (для модерации)
- `POST /books/approve` — подтверждение книги

### Жанры
- `GET /genres` — получение списка жанров
- `POST /genres` — создание нового жанра
- `DELETE /genres/:id` — удаление жанра

### Авторы
- `POST /authors` — создание автора
- `DELETE /authors/:id` — удаление автора

### Пользователи
- `POST /auth/register` — регистрация
- `POST /auth/login` — вход
- `POST /auth/logout` — выход

## Установка и запуск

Проект можно запустить двумя способами: в Docker (MySQL поднимается сама)
или локально на установленных Node.js и MySQL.

### Запуск в Docker

Требуется Docker с плагином Compose. Отдельно ставить Node.js и MySQL не нужно.

1. **Подготовить переменные окружения:**
   ```bash
   cp .env.example .env
   ```
   Для Docker достаточно задать `DB_PASSWORD` и `JWT_SECRET` — остальное
   подставит `docker-compose.yml`.

2. **Запустить:**
   ```bash
   docker compose up --build
   ```
   Приложение стартует только после того, как MySQL пройдёт healthcheck,
   и само создаёт таблицы через `sequelize.sync()` — отдельный прогон
   миграций для первого запуска не нужен.

3. **Открыть:** http://localhost:3000
   Порт на хосте задаётся переменной `APP_PORT` в `.env` (по умолчанию 3000).
   Если 3000 уже занят другим сервисом, `docker compose up` упадёт с
   `Bind for 0.0.0.0:3000 failed: port is already allocated` — поставьте
   `APP_PORT=3001` и запустите снова. Внутри контейнера приложение всегда
   слушает 3000, переменная `PORT` на Docker-запуск не влияет.

4. **Создать роли и назначить суперадминистратора** — один раз, после того
   как зарегистрирован первый пользователь (скрипт выдаёт роль пользователю с `id = 1`):
   ```bash
   docker compose exec -T db sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" book_app_db' < sql_scripts/add_super_admin.sql
   ```

Остановить — `docker compose down`, остановить и удалить данные БД вместе
с загруженными книгами — `docker compose down -v`. Пока volume'ы не удалены,
книги, обложки и содержимое базы переживают пересборку образа.

### Локальный запуск

#### Предварительные требования
- Node.js (версия 16 или выше)
- MySQL
- npm

#### Инструкция

1. **Клонировать репозиторий:**
   ```bash
   git clone https://github.com/yourusername/e-library.git
   cd e-library
   ```

2. **Установить зависимости:**
   ```bash
   npm install
   ```

3. **Настроить переменные окружения:**

   Скопируйте шаблон и заполните значения:
   ```bash
   cp .env.example .env
   ```

   ```env
   DB_HOST=localhost
   DB_USER=your_user
   DB_PASSWORD=db_pass
   DB_NAME=library_db
   JWT_SECRET=сгенерируйте_через_openssl_rand_hex_32
   BOOK_UPLOAD_PATH=uploads/books
   PORT=3000
   ```

   Все переменные, кроме `PORT` и `APP_PORT`, обязательны — без них сервер
   не стартует. `APP_PORT` используется только при запуске через Docker.
   Файл `.env` в репозиторий не коммитится.

4. **Запустить базу данных и применить миграции:**
   ```bash
   npx sequelize db:migrate
   ```

5. **Запустить сервер:**
   ```bash
   npm start
   ```

6. **Открыть приложение:**
Перейдите в браузере по адресу: http://localhost:3000

## Безопасность и валидация
- Загрузка файлов разрешена только в формате `.epub`.  
- Все пользовательские данные экранируются (`escapeHtml`) для предотвращения XSS.  
- Доступ к защищённым маршрутам — только после аутентификации и проверки роли.  
- Логирование всех действий в таблице `action_history`.
